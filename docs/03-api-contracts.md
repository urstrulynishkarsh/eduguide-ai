# 3. API contracts

The always-current, clickable version of this document is generated by the running backend at
**<http://localhost:8000/docs>**. This file explains the rules behind it and what is planned.

## 3.1 Conventions

| Topic | Rule |
|---|---|
| Base path | `/api/v1` (health checks are at `/health`, outside the version) |
| Format | JSON in, JSON out, UTF-8 |
| Signing in | `Authorization: Bearer <access_token>` on every request except `/auth/register`, `/auth/login`, `/auth/refresh`, `/meta/*`, `/health*` |
| Ids | UUID strings |
| Dates | ISO 8601 in UTC, e.g. `2026-10-07T05:13:36.747094Z` |
| Fixed values | lower-case codes (`class_7`, `cbse`, `hinglish`). Labels for people come from `/meta/options` |
| Who am I | Taken from the token only. No endpoint accepts a parent id or account id in the body |
| Tracing | Every response has an `X-Request-ID` header. Quote it when reporting a problem |

### Errors

Every error, from every endpoint, has this shape:

```json
{
  "error": {
    "code": "student_not_found",
    "message": "We couldn't find this student.",
    "details": null
  }
}
```

- `code` never changes; the frontend uses it to pick a translated message.
- `message` is plain English, safe to show to a parent.
- `details` is a list of `{ "field", "message" }` for form errors, otherwise `null`.

| HTTP | `code` | When |
|---|---|---|
| 401 | `not_authenticated` | No token was sent |
| 401 | `invalid_token` | Token expired, damaged, of the wrong kind, or its child no longer exists |
| 401 | `invalid_credentials` | Wrong email or password (the same answer for both, on purpose) |
| 403 | `parent_required` | A student session tried something only a parent may do |
| 404 | `student_not_found` | No such student — **or it belongs to another family** |
| 404 | `not_found` | Unknown URL |
| 409 | `email_already_registered` | Sign-up with an email that already has an account |
| 409 | `student_limit_reached` | More children than `MAX_STUDENTS_PER_PARENT` |
| 404 | `book_not_found` · `document_not_found` · `chapter_not_found` · `topic_not_found` · `exercise_not_found` | No such thing — **or it belongs to another family** |
| 409 | `book_limit_reached` · `document_limit_reached` | More than `MAX_BOOKS_PER_ACCOUNT` / `MAX_DOCUMENTS_PER_BOOK` |
| 409 | `document_already_uploaded` | The same file (same content) is already in this book |
| 409 | `document_not_failed` | Retry asked for a document that did not fail |
| 413 | `file_too_large` · `payload_too_large` | Upload over `MAX_UPLOAD_MB`; any other request body over 1 MB |
| 415 | `unsupported_file_type` | Not a PDF, DOCX or TXT (decided from the content, not the name). The message says what to do, e.g. for photos or old `.doc` files |
| 422 | `password_protected` · `file_unreadable` · `empty_file` · `too_many_pages` · `text_encoding_unsupported` | The file was checked and refused at upload |
| 422 | `invalid_cursor` | A damaged `cursor` in a list request |
| 422 | `insufficient_context` | "I couldn't find enough information in your uploaded material to answer this reliably." |
| 422 | `profile_required` | The learner has no class details yet |
| 404 | `practice_not_found` · `question_not_found` | No such practice (or another family's), or the question is not in it |
| 422 | `question_type_not_for_class` | The question type is not used for the learner's class (e.g. `numerical` in Class 7) |
| 422 | `practice_not_ready` · `answer_does_not_fit` | The practice is still `preparing`; the answer does not fit the question's format (practice and tests) |
| 404 | `test_not_found` · `test_attempt_not_found` · `study_plan_not_found` · `plan_item_not_found` · `chat_not_found` | No such test, sitting, plan, plan task or conversation (or another family's) |
| 422 | `test_not_for_class` | The kind of test, or a time limit, is not used for the learner's class (`details` names `kind` or `duration_minutes`) |
| 422 | `test_not_ready` · `test_time_over` · `test_already_submitted` · `test_not_submitted` | Started while still `preparing`; an answer after the deadline; an answer after submitting; a report before submitting |
| 422 | `ai_declined` | The AI declined the request for safety reasons |
| 503 | `ai_not_configured` · `ai_unavailable` | AI switched off (`LLM_PROVIDER=none`); provider busy or unreachable |
| 422 | `validation_error` | A field is missing or malformed; see `details` |
| 422 | `invalid_learning_profile` | Class, stream and goal do not fit together; see `details` |
| 500 | `internal_error` | Our bug. The details are in the server log under the request id |

Submitted values are never echoed back in errors (they can contain passwords).

### Onboarding flow

```
Parent:   POST /auth/register {role: "parent"}  →  POST /students            →  dashboard
Student:  POST /auth/register {role: "student"} →  PUT /students/{id}/profile →  home
                                                   (id comes from GET /auth/me → active_student.id)
```

`GET /auth/me` returns `onboarding_complete: false` until that second call has happened, so the
frontend always knows whether to show the onboarding screen.

### Register / login

```http
POST /api/v1/auth/login
{ "email": "parent@example.com", "password": "DemoParent123" }
```

```json
{
  "user": {
    "id": "3477f7cd-fc38-45d1-93f7-d08d238dd8e2",
    "email": "parent@example.com",
    "full_name": "Sunita Sharma",
    "role": "parent",
    "preferred_language": "hinglish",
    "created_at": "2026-10-07T05:13:36.747094Z"
  },
  "tokens": {
    "access_token": "eyJhbGciOiJIUzI1NiIs...",
    "refresh_token": "eyJhbGciOiJIUzI1NiIs...",
    "token_type": "bearer",
    "expires_in": 1800
  }
}
```

`POST /auth/register` takes `role`, `full_name`, `email`, `password` (8–128 characters) and an
optional `preferred_language`, and returns the same shape with status `201`.

`POST /auth/refresh` takes `{ "refresh_token": "..." }` and returns a new `tokens` object.

### Add a child

```http
POST /api/v1/students
Authorization: Bearer <parent access token>

{
  "name": "Aarav",
  "age": 12,
  "profile": {
    "class_level": "class_7",
    "board": "cbse",
    "medium": "en",
    "primary_language": "hinglish",
    "subjects": ["Mathematics", "Science", "Social Science", "English", "Hindi"]
  }
}
```

```json
{
  "id": "6ecc2ac7-8576-45e4-8bb1-d546162159be",
  "name": "Aarav",
  "age": 12,
  "has_own_login": false,
  "profile": {
    "class_level": "class_7",
    "board": "cbse",
    "board_name": null,
    "medium": "en",
    "primary_language": "hinglish",
    "stream": null,
    "goal": "school_exam",
    "subjects": ["Mathematics", "Science", "Social Science", "English", "Hindi"],
    "class_label": "Class 7",
    "band": "middle"
  },
  "created_at": "2026-10-07T05:13:36.760094Z",
  "updated_at": "2026-10-07T05:13:36.760097Z"
}
```

Profile rules (checked against the class profile):

| Field | Rule |
|---|---|
| `class_level` | required — everything else depends on it |
| `board` | required. `board_name` is kept only for `state` / `other` |
| `medium` | any code from `/meta/options → mediums`; default `en` |
| `primary_language` | `en`, `hi` or `hinglish`; default `en` |
| `stream` | **required** for `class_11` / `class_12`, **refused** for every other class |
| `goal` | optional; when missing, the default goal of the class is used. Must be allowed for the class. `jee` / `neet` need `stream: "science"` |
| `subjects` | up to 15 names of at most 60 characters; blanks and repeats are removed |

### Child mode

```http
POST /api/v1/students/6ecc2ac7-8576-45e4-8bb1-d546162159be/session
Authorization: Bearer <parent access token>
```

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "expires_in": 43200,
  "student": { "...": "the child, same shape as above" }
}
```

The frontend switches to this token while the child uses the app. With it, `GET /auth/me` returns
`"active_role": "student"` and `"active_student"` = this child. There is no refresh token. The frontend
deletes the parent's refresh token while child mode is on, so when the child session expires the
parent signs in again (docs/04 §4.6).

| Method | Path | Who | Purpose |
|---|---|---|---|
| POST | `/api/v1/books` | parent, solo student | Add a book (empty; files come next) |
| GET | `/api/v1/books?limit=&cursor=&student_id=` | signed in | My Learning Library, newest first, paginated |

| GET | `/api/v1/documents/{id}` | owner | Progress checklist and result of one file |
| POST | `/api/v1/documents/{id}/retry` | parent, solo student | Read a failed file again |

| GET | `/api/v1/books/{id}/chapters` | owner | Chapters, in chapter order |
| GET | `/api/v1/chapters/{id}` | owner | A chapter: topics, exercises, example count, summary |
| PATCH | `/api/v1/chapters/{id}` | parent, solo student | Rename a chapter or fix its number |
| GET | `/api/v1/exercises/{id}` | owner | The questions of an exercise as printed in the book, with sources |

**Child mode** sees the family's shared books plus the books for that child, and can read them all,
but cannot add, change or delete anything (`403 parent_required`). A student who signed up alone
manages their own books; their books are linked to them automatically.

### Create a book, then upload

```http
POST /api/v1/books
{ "title": "Class 7 Mathematics", "subject": "Mathematics", "student_id": "6ecc2ac7-…" }
```

Class, board and language may be left out when `student_id` is given — they come from the child's
profile. Without a child, `class_level` is required. `material_type` defaults to `textbook`.

```http
POST /api/v1/books/{book_id}/documents
Content-Type: multipart/form-data   (field "file")
```

```json
{
  "id": "54a82a82-…",
  "book_id": "b7275ab3-…",
  "original_filename": "jemh102.pdf",
  "file_type": "pdf",
  "size_bytes": 2483021,
  "page_count": 18,
  "status": "queued",
  "stage": null,
  "progress": [
    { "step": "extract_text", "state": "pending" },
    { "step": "detect_chapters", "state": "pending" },
    { "step": "detect_exercises", "state": "pending" },
    { "step": "detect_topics", "state": "pending" },
    { "step": "make_chunks", "state": "pending" }
  ],
  "error": null,
  "summary": { "chapters": null, "exercises": null, "questions": null, "...": null },
  "created_at": "…", "updated_at": "…", "processing_finished_at": null
}
```

Poll `GET /documents/{id}` (every 1–2 seconds is plenty). Each step goes `pending → active → done`;
`status` ends as `ready` or `failed`. The frontend shows the steps in parent words
([doc 4, 4.5](04-frontend-routes.md)). When `failed`, `error.message` can be shown as it is:

| `error.code` | Meaning |
|---|---|
| `scanned_document` | Only scanned pages and OCR is switched off |
| `no_text_found` | The file has no text we could use |
| `file_unreadable` · `processing_failed` | "We couldn't process this document. Please try another PDF." |
| `file_missing` | The stored file is gone; upload it again |

## 3.4 Endpoints added in Step 3 — Learn

| Method | Path | Who | Purpose |
|---|---|---|---|
| POST | `/api/v1/learn/explain` | signed in | Explain a concept from the child's own books, with sources |

```http
POST /api/v1/learn/explain
{ "question": "2x + 4 = 10 kaise solve karein?", "student_id": "6ecc2ac7-…", "style": "hinglish" }
```

`student_id` is needed for a parent and ignored in a student session (which always uses itself).
Optional `book_id` or `chapter_id` narrow the search; otherwise every book the session may see,
for the learner's class, is searched. `style`: `normal`, `simple`, `like_10` ("Explain like I'm
10"), `hindi`, `hinglish`; `normal` writes in the learner's language.

```json
{
  "explanation": "Pehle dono taraf se 4 ghatao …",
  "steps": ["2x + 4 - 4 = 10 - 4, so 2x = 6", "x = 6 ÷ 2 = 3"],
  "style": "hinglish",
  "origin": "generated",
  "sources": [
    { "book_id": "…", "book_title": "Class 8 Mathematics",
      "chapter": "Chapter 2 Linear Equations in One Variable", "exercise": null, "page": 3 }
  ]
}
```

`sources` lists only the passages the explanation used. When the books do not cover the question,
the answer is `422 insufficient_context` — the AI is never asked to answer from memory.

The upload checklist has a sixth step, `embed_chunks`, after `make_chunks`.

### Create Practice

```http
POST /api/v1/practice/sessions
{ "student_id": "6ecc2ac7-…", "exercise_id": "…", "count": 5, "difficulty": "mixed",
  "question_type": "mcq", "language": "hinglish" }
```

At most one of `book_id`, `chapter_id`, `topic_id` (Step 7), `exercise_id`; none = every book of the
learner's class.
`count` defaults to the class's usual number (doc 7, 7.4) and may not exceed its maximum.
`question_type` is `mixed` or one format the class allows. `language` defaults to the learner's.

The answer is `201` with `status: "ready"` when saved questions the learner has never been given
cover it, otherwise `status: "preparing"` while the rest are written and checked in the background
— poll `GET /practice/sessions/{id}`. When the AI is off and saved questions are not enough:
`503 ai_not_configured`. A session that could not be prepared ends `failed` with `error.code`
`insufficient_context`, `ai_unavailable` or `generation_failed` and a message for the parent.

```json
{
  "id": "…", "status": "ready", "question_count": 5, "answered": 0, "correct": 0,
  "items": [
    {
      "question": {
        "id": "…", "number": 1, "format": "mcq", "style": "application", "difficulty": "medium",
        "text": "Riya ke paas kuch pencils hain …", "options": ["12", "14", "16", "26"],
        "case": null, "match_left": [], "match_right": [], "unit": null,
        "origin": "generated",
        "source": { "book_title": "Class 7 Mathematics", "chapter": "Chapter 4 Simple Equations", "exercise": "4.2", "page": 61, "book_id": "…" }
      },
      "attempts": 0, "correct": null, "hints_shown": 0, "hints_total": 2, "steps_shown": false, "answer_shown": false
    }
  ]
}
```

### Answering

Send the field that fits the format: `option` (mcq, true_false, assertion_reason, case_based,
visual_choice), `value` (numerical, counting), `text` (fill_blank, short_answer, long_answer) or
`pairs` (matching — for each left item, the index of its right item).

```http
POST /api/v1/practice/sessions/{id}/answers
{ "question_id": "…", "option": 1, "time_taken_ms": 14000 }
```

```json
{ "correct": false, "try_again": false, "feedback": null, "correct_answer": "p = 14", "session_completed": false }
```

Written answers are marked by the AI (`feedback` says what was right and what to add). For
Nursery–Class 2 a wrong answer gives `try_again: true` and no `correct_answer`: the child is
invited to try again, and "Show Answer" is there when they want it.

## 3.6 Endpoints added in Step 7 — Adaptive learning

| Method | Path | Who | Purpose |
|---|---|---|---|
| GET | `/api/v1/students/{id}/mastery` | owner | Mastery of every area practised, weakest first |
| GET | `/api/v1/students/{id}/recommendations` | owner | Recommended for You, today |

"Owner" is the same rule as progress: a parent for their children, a student or child-mode session
for itself only; anyone else gets `404 student_not_found`. A learner without class details gets
`422 profile_required`. An *area* is a topic, or a chapter (`topic: null`) for questions without one.
How the numbers are worked out: doc 7, 7.9.

```json
{
  "student_id": "6ecc2ac7-…",
  "areas": [
    {
      "book_id": "…", "book_title": "Class 7 Mathematics",
      "chapter_id": "…", "chapter": "Chapter 4 Simple Equations",
      "topic_id": "…", "topic": "4.3 Equations in Daily Life",
      "status": "needs_attention", "mastery": 0.31, "confidence": 0.6, "accuracy": 0.33,
      "attempts": 6, "avg_time_ms": 41000, "difficulty": "easy",
      "last_practised_at": "2026-11-03T10:12:00Z"
    }
  ]
}
```

`status` is `needs_attention` (below 60 % right over at least 5 answers; Class 6–12 only), `strong`
(mastery 0.85 or more over at least 5 answers) or `learning`. `difficulty` is the level for the next
practice of that area; `null` where the class has no adaptive difficulty (Nursery–Class 5).

```json
{
  "student_id": "6ecc2ac7-…",
  "day": "2026-11-03",
  "items": [
    {
      "id": "…", "kind": "strengthen", "status": "active",
      "book_id": "…", "book_title": "Class 7 Mathematics",
      "chapter_id": "…", "chapter": "Chapter 4 Simple Equations",
      "topic_id": "…", "topic": "4.3 Equations in Daily Life",
      "reason": "33% right in the last 6 answers. Revise the idea, then practise easy questions.",
      "practice": { "student_id": "6ecc2ac7-…", "topic_id": "…", "chapter_id": null, "book_id": null,
                    "exercise_id": null, "count": null, "difficulty": "easy", "question_type": "mixed",
                    "language": null },
      "revise": { "question": "4.3 Equations in Daily Life", "student_id": "6ecc2ac7-…",
                  "book_id": null, "chapter_id": "…", "style": "normal" }
    }
  ]
}
```

At most three, made on the first request of the day (India time) and kept for that day: `strengthen`
(a weak area: revise, then easier questions) · `continue` (an area being learned) · `review` (not
practised for 7 days) · `new_chapter` (never practised). **Start Recommended Practice** sends
`practice` as-is to `POST /practice/sessions`; `revise` (strengthen only) goes as-is to
`POST /learn/explain`. Finishing a practice of that place turns `status` to `done`.

### Mock tests

```http
POST /api/v1/mock-tests
{ "student_id": "6ecc2ac7-…", "kind": "chapter", "chapter_id": "…", "count": 15 }
```

| `kind` | From | Place | Default questions | Time limit |
|---|---|---|---|---|
| `practice` | Class 3 (`practice_tests`) | any one of book / chapter / topic / exercise, or none (all books) | the class's usual number | optional, Class 9+ |
| `chapter` | Class 6 (`chapter_tests`) | `chapter_id`, required | 15 | optional, Class 9+ |
| `full_mock` | Class 9 (`full_mock_tests`) | `book_id`, or none | 30 | always; about 2 minutes a mark unless `duration_minutes` is given |

A time limit (`duration_minutes`, 5–240) needs `timed_tests` (Class 9+). The paper has sections
like a board paper, each kept only when the class uses one of its formats: **A** objective
(MCQ, true/false, fill in the blank, assertion-reason, case-based, 1 mark each), **B** numerical
(2 marks), **C** short answer (2 marks), **D** long answer (5 marks). Questions come as in practice:
saved questions the learner has never been given (in a practice or a test) first, the rest written
in the background — `status: "preparing"` until `ready` (or `failed` with `error`), and
`503 ai_not_configured` at once when the AI is off and the bank is short.

```json
{
  "id": "…", "kind": "chapter", "status": "ready", "chapter": "Chapter 4 Simple Equations",
  "book_id": "…", "book_title": "Class 7 Mathematics", "topic": null, "exercise": null,
  "question_count": 15, "total_marks": 31, "duration_minutes": null, "difficulty": "mixed",
  "sections": [
    { "code": "A", "title": "Objective questions", "marks": 1, "questions": [ { "number": 1, "format": "mcq", "…": "…" } ] },
    { "code": "C", "title": "Short answer questions", "marks": 2, "questions": [ "…" ] },
    { "code": "D", "title": "Long answer questions", "marks": 5, "questions": [ "…" ] }
  ],
  "attempts": [ { "id": "…", "started_at": "…", "submitted_at": null, "score": null } ]
}
```

**Taking it.** `POST /mock-tests/{id}/attempts` starts the clock (`deadline` = start + time limit).
Answers are saved one at a time with `PUT …/answers/{question_id}` and can be changed until
submitted, so a reload loses nothing. A test has no hints, steps or explanations. After the deadline
and one minute of grace, saving answers `422 test_time_over`; the screen submits when the time runs
out, and a late `submit` still marks what was saved. After a submitted sitting, `POST …/attempts`
is a retake of the same paper.

**Marking.** Choice, number, blank and matching answers exactly; written answers by the AI, which
also counts the key points covered: a written answer earns that share of its marks, to the nearest
half mark (2 of 4 key points of a 5-mark answer = 2.5). One AI call per written answer; if the AI
fails, nothing is stored and `submit` can be sent again. Every answer becomes a question attempt with
its marks, so progress and mastery count it; questions left out earn nothing and are not counted.

                   "response": { "text": "…" }, "feedback": "Add the other two points.",
                   "solution": { "concept": "…", "steps": ["…"], "final_answer": "…" } } ]

### Study planner

```http
POST /api/v1/study-plans
{ "student_id": "6ecc2ac7-…", "exam_date": "2026-12-10", "daily_minutes": 45, "target_score": 80,
  "chapter_ids": [] }
```

`exam_date` after today (India time), at most a year ahead; `daily_minutes` 10–300 (default 30);
`target_score` 40–100 (default 80); `chapter_ids` empty = every chapter of the learner's books for
their class. Not in child mode (`403 parent_required`); a child can tick tasks off.

The tasks are made by rules from the learner's mastery, not by the AI: a weak topic first (learn the
idea, then practise at its lowered level); each new chapter (learn, then practise); a chapter below
the target practised at its level as often as it needs to get there — about one practice for every
25 points of mastery it lacks, the second and later ones in rounds through the chapters so they are
spread out; a chapter at or above the target (one review near the end); and on the last day a test
of each book — a full mock test from Class 9, a practice test in
Class 3–8, none below. Learn takes 15 minutes, practice 20, a test its length. The final tasks go on
the last days, the rest are spread evenly before them within `daily_minutes`; what does not fit is
counted in `unscheduled`.

**It follows performance.** On the first `GET` of each day (India time) the days from today on are
planned again from the latest mastery: tasks of past days still pending become `missed`, done and
skipped ones stay. Finishing a practice of a task's place, or submitting a test of its book, marks
the task `done`; learn tasks are ticked off with `PATCH`.

  "days": [
    { "day": "2026-11-04", "minutes": 35, "items": [
      { "id": "…", "kind": "learn", "status": "pending", "minutes": 15, "difficulty": "mixed",

### Conversations

**Who:** `assistant` conversations are for a parent, about one of their children (a student or
child-mode session gets `403 parent_required`). `tutor` conversations belong to a learner: a child
in child mode or a student who signed up alone uses its own, and the parent may read them too.
Anyone else gets `404 chat_not_found`.

**A message.** A small, fast AI call first works out what was asked; the child's books are searched
when needed; then the reply streams back as Server-Sent Events:

```
event: delta
data: {"text": "Equation ek balance hai"}

event: done
data: {"question": {ChatMessageOut}, "answer": {ChatMessageOut}}
```

or `event: error` with `{"code", "message"}` (busy, declined). The question and the reply are saved
together only with `done`: after an `error` nothing is saved and the text can be sent again. Errors
found before the reply starts are ordinary JSON errors: `503 ai_not_configured`, `422
insufficient_context` (the tutor asked about something the books do not cover).

```json
{ "id": "…", "role": "assistant", "content": "Equation ek balance hai…",
  "sources": [ { "book_title": "Class 7 Mathematics", "chapter": "Chapter 4 Simple Equations", "page": 61, "…": "…" } ],
  "rung": "hint_1", "created_at": "…" }
```

Replies mark the book passages they use (`[S1]`); the marks are taken out of `content` and become
`sources`.

**The tutor's hint ladder** (docs/06 §6.5): `rung` says how much help a reply gave —
`hint_1` → `hint_2` → `concept` → `steps` → `answer`. A new problem starts at `hint_1`; each request
for more help, "just tell me the answer" included, moves one rung; "hints only" stops at `hint_2`
for that problem; an attempt is checked, and if wrong, answered with the next rung. Concept
questions, chat and off-topic messages have `rung: null`.

**The parent assistant** answers from the app's own numbers (the dashboard, every topic practised,
overall progress) and, for questions about the books, from the child's books with sources. The
child's name is not sent to the AI.

### Previous-year papers

A book with `material_type: "previous_year_paper"` holds one paper per file. Reading such a file
(docs/05 §5.2) makes the file one chapter named after it, its sections ("Section A", "Part A –
Physics · Section B") its exercises and every numbered question an exercise question, so the book page
lists each paper's questions as printed.

`POST …/paper-analysis` reads every paper again with the AI, one background job per paper: each
question's marks, format and the chapter or topic of the family's textbooks of the same class that
teaches it (chosen from a numbered list, the paper's subject first), and the paper's year (else from
the file name), time and negative marking. `422 not_a_paper_book`, `not_for_class` (below Class 9),
`no_papers`; `503 ai_not_configured`; `403 parent_required` in child mode.

`status`: `none` (never analysed), `preparing`, `ready`, `failed`; a paper added since is `new`. A

**A test like the papers** (`kind: "previous_year"`, `book_id` = the paper book, Class 9+): the
latest paper's sections in order, with their marks (a section's title is its kind of question, e.g.
"Short answer questions"), as many questions as that paper has (at most the class's 50) or `count`;
each section's questions spread over the chapters of the learner's own books by their marks in the
papers; objective sections lose the paper's negative marks; always timed at the paper's pace (its
time ÷ its marks; 2 minutes a mark when it shows no time). The learner must be in the papers' class
(`422 paper_not_for_class`); the papers must be analysed with a question matching one of the
learner's chapters (`422 paper_not_analysed`).

### Exam modes and negative marking

A Class 11–12 learner (`competitive_exam_modes`) whose goal is `jee`, `neet` or `cuet` gets every
test in that exam's pattern (`exam` on the test). NTA's 2026 patterns, to check each year:

| `exam` | Sections | Marks | Pace |
|---|---|---|---|
| `jee` | A objective (MCQ, assertion-reason) 80 % · B numerical 20 % | +4 / −1 | 180 min for 300 marks |
| `neet` | A objective (MCQ, assertion-reason) | +4 / −1 | 180 min for 720 marks |
| `cuet` | A objective (MCQ, assertion-reason, case-based) | +5 / −1 | 60 min for 250 marks |

A wrong answer earns `−negative` marks (the question attempt's `marks`), a question left out 0, so a
score can be below zero; mastery still counts right and wrong. Board papers have `negative: 0`. The
study plan's final test is timed in the same pattern.

### Words the screens put together

The backend writes no sentence a screen shows besides its error messages (English, for developers
and as the fallback). Recommendation and plan-task `reason`s are a code with its numbers, e.g.
`{"code": "weak", "accuracy": 0.2, "answers": 5, "difficulty": "easy", "days": null, "mastery": null,
"aim": null}` (codes in `schemas/adaptive.Reason`); the frontend words them in the screen language
(`frontend/lib/copy`). Error messages and option labels are translated there by their `code`.

### Rewards

```json
{
  "student_id": "…", "xp": 110, "level": 2, "level_xp": 10, "level_size": 150,
  "streak": 3, "longest_streak": 5, "today": { "answered": 4, "goal": 10 },
  "badges": [ { "code": "first_practice", "earned_at": "…" }, { "code": "right_10", "earned_at": null } ]
}
```

XP: the first answer to a question in a practice or a test sitting +2, right the first time +8 more;
a finished practice or a submitted test +20; the day's goal (the class's usual practice length)
+10. Trying again and hints earn and cost nothing. Level *n* → *n*+1 takes 100, 150, 200, … XP. The
streak counts days in a row (India time) with an answer and is kept until the end of the next day.
Badges: `first_practice`, `perfect_practice`, `right_10`, `right_100`, `streak_3`, `streak_7`,
`streak_30`, `first_test`, `topic_mastered`, `mistake_fixed`, `level_5` (earned first, newest first,
then the rest). An answer (`POST /practice/sessions/{id}/answers`) also returns what it earned:
`"rewards": {"xp": 30, "badges": ["first_practice"]}`.

### Progress over time

`weeks` has the dashboard's `week` shape, one entry a week (`day` is its Monday); `subjects`,
`formats` and `difficulties` are `[{"code", "answered", "accuracy"}]`, most answered first (first
answers, as everywhere); `tests` are the dashboard's test results, oldest first.

## 3.11 Rules for every endpoint

No endpoints are planned for Step 12 (production hardening). Rules that hold for all endpoints:

- Lists that can grow use cursor pagination: `?limit=20&cursor=...` → `{ "items": [...], "next_cursor": "..." }`.
- Anything produced with the help of the child's books returns a `source` object (book, chapter,
  exercise, page), and generated questions are marked `"origin": "generated"`.
- When the books do not contain enough to answer reliably, the API says so with the code
  `insufficient_context` instead of guessing.
